========================================
        Технический проект
 Система управления базами данных
========================================

1. Внешняя часть — программный интерфейс
=========================================

Основная точка входа — **класс ``Database``** из модуля ``db.py``.

**Публичные методы:**

- ``create_table(table_name, columns)`` — создать таблицу;
- ``drop_table(table_name)`` — удалить таблицу;
- ``alter_table(table_name, new_columns)`` — изменить структуру;
- ``insert(table_name, values)`` — добавить строку;
- ``select(table_name, fields="*")`` — получить строки с выбором полей.

**Принципы работы:**

- **Успех = тишина.** Метод завершился без исключения — значит всё сработало без ошибок.
- **Ошибка = исключение.** Пользователь сам решает, как реагировать.
- **Объект — один на всю работу.** Создаётся один раз через
  ``Database("database")``.

**Пример использования:** ::

    db = Database("database")
    db.create_table("users", ["id", "name", "age"])
    db.insert("users", ["1", "Вася", "20"])

    # select возвращает объект Result
    result = db.select("users", "name,age")

    # Результат можно фильтровать через лямбду
    filtered = result.filter(lambda rec: int(rec["age"]) > 18)


2. Внутренняя часть — реализация
=================================

Внутри класса выделены **приватные методы** — они не предназначены
для вызова клиентом и помечены символом ``_`` в начале имени.

**Приватные методы:**

- ``_table_file(table_name)`` — возвращает путь к файлу таблицы;
- ``_read_lines(filename)`` — читает файл и возвращает список строк;
- ``_write_lines(filename, lines)`` — записывает строки в файл;
- ``_load_schema()`` — читает схему из ``schema.txt``;
- ``_save_schema()`` — сохраняет схему в ``schema.txt``.

**Атрибуты объекта ``Database``:**

- ``self.folder`` — путь к папке базы данных;
- ``self.schema_file`` — путь к файлу схемы;
- ``self.schema`` — словарь со структурой базы, загружается один раз
  при создании объекта.

**Почему так:** схема и пути хранятся в объекте — не нужно
читать файл или собирать путь при каждом вызове метода.
Это ускоряет работу.

**Класс ``Result`` (результат выборки):**
Этот класс возвращается методом ``select``. Он нужен для удобной работы с данными.
- ``self.fields`` — список выбранных колонок;
- ``self.rows`` — сами данные (список списков);
- ``add(row)`` — добавляет строку в результат;
- ``to_dicts()`` — превращает строки в список словарей (чтобы обращаться к полям по имени);
- ``filter(func)`` — фильтрует данные с помощью переданной лямбда-функции.


3. Принятые решения и их обоснование
=====================================

**Класс вместо набора функций.**
Схема читается один раз при создании объекта и хранится в памяти.
При работе с функциями схему пришлось бы читать при каждом вызове.

**Один файл на таблицу.**
Структура и данные разделены: схема в ``schema.txt``,
данные таблиц в отдельных файлах. Это упрощает поиск, изменение
структуры и масштабирование.

**Разделитель — символ ``|``.**
Редко встречается в данных, не требует библиотек для парсинга.
Простое разбиение строки через ``split("|")``.

**Модуль ``os`` — только для файловой системы.**
``os.makedirs`` — для создания папки, ``os.remove`` — для удаления
файла. Чтение и запись данных — через встроенный ``open``.

**Свои классы исключений.**
``DBError`` — базовое исключение, от него наследуются
``TableAlreadyExists``, ``TableNotFound``, ``ColumnNotFound``.
Это позволяет ловить как конкретную ошибку, так и все ошибки СУБД
одной строкой.

**``ValueError`` — стандартное исключение.**
Для неверного числа значений при вставке используется стандартное
исключение Python. Свой класс не нужен — стандартного достаточно.

**``select`` с выбором полей.**
Второй параметр ``fields`` позволяет выбрать любой набор полей
в любом порядке, включая дубли. Это даёт гибкость клиенту.

**Возврат объекта ``Result`` вместо матрицы.**
Метод ``select`` возвращает объект класса ``Result``. Это позволяет добавить в результат метод ``filter`` для фильтрации данных через лямбда-функции прямо в процессе работы. Фильтрация преобразует строки в словари, передает их в лямбду и возвращает новый объект ``Result`` с отфильтрованными строками.


4. Алгоритмы работы
====================

**create_table:** ::

    1. Проверить, нет ли таблицы в self.schema.
       Если есть — кинуть TableAlreadyExists.
    2. Добавить таблицу в self.schema.
    3. Сохранить схему через _save_schema.
    4. Создать пустой файл данных таблицы.

**drop_table:** ::

    1. Проверить, есть ли таблица в self.schema.
       Если нет — кинуть TableNotFound.
    2. Удалить таблицу из self.schema.
    3. Сохранить схему.
    4. Удалить файл данных через os.remove.

**insert:** ::

    1. Проверить, есть ли таблица.
    2. Получить список колонок из self.schema.
    3. Проверить, что число значений совпадает с числом колонок.
       Если нет — кинуть ValueError.
    4. Прочитать текущие строки файла.
    5. Добавить новую строку.
    6. Записать файл.

**select:** ::

    1. Проверить, есть ли таблица.
    2. Если fields == "*" — выбрать все колонки.
       Иначе — разбить строку по запятой.
    3. Для каждого поля проверить, что оно есть в self.schema.
       Если нет — кинуть ColumnNotFound.
    4. Найти индексы выбранных колонок в self.schema.
    5. Создать объект Result с выбранными полями.
    6. Для каждой строки данных собрать значения по индексам и добавить в Result.
    7. Вернуть объект Result.

**filter (внутри класса Result):** ::

    1. Создать пустой Result для отфильтрованных данных.
    2. Превратить все строки в словари через to_dicts.
    3. Для каждой строки:
       а) Передать словарь в лямбда-функцию.
       б) Если функция вернула True — добавить оригинальную строку в новый Result.
    4. Вернуть новый Result.

**Пример работы select и filter:** ::

    result = db.select("users", "name,age")
    filtered = result.filter(lambda rec: int(rec["age"]) > 18)
