========================================
Архитектура проекта
========================================

1. Общая структура проекта
===========================

    my_db/
     ├── db.py                — движок СУБД
     ├── main.py              — демонстрация программного интерфейса
     ├── tests.py             — тесты функций
     ├── tests_uncaught.py    — демонстрация непойманного исключения
     ├── ТЗ.rst               — техническое задание
     ├── ARCHITECTURE.rst     — этот файл
     └── database/            — папка с файлами базы данных
          ├── schema.txt       — схема базы (структура)
          ├── users.txt        — данные таблицы users
          └── orders.txt       — данные таблицы orders


1.1. Что внутри папки database/
--------------------------------

::

    database/                       ← БАЗА ДАННЫХ
     │
     ├── schema.txt                  ← СТРУКТУРА
     │    users|id,name,age,email
     │    orders|id,user_id,amount
     │
     ├── users.txt                   ← ТАБЛИЦА users
     │    1|Вася|20|vasya@mail.ru
     │    2|Петя|22|petya@mail.ru
     │
     └── orders.txt                  ← ТАБЛИЦА orders
          1|1|500
          2|2|1200


2. Назначение файлов
=====================

db.py
-----

**Движок СУБД.** Содержит:

- классы исключений;
- вспомогательные функции работы с файлами;
- функции работы со схемой;
- 5 функций интерфейса.

**Библиотеки не используются** — только встроенные функции Python.

main.py
-------

**Демонстрация** программного интерфейса. Ловит исключения через
``try/except``. При успехе функция молчит — программа не комментирует
каждый шаг.

tests.py
--------

**Тесты** функций интерфейса. Проверяют успешные и ошибочные сценарии.

tests_uncaught.py
-----------------

**Демонстрация** непойманного исключения. Специально не ловит ошибку —
показывает аварийное завершение программы.

database/
---------

**Папка с файлами базы данных.** Создаётся вручную


3. Формат хранения данных
==========================

База данных — это **папка** ``database/``. Внутри неё:

- ``schema.txt`` — **схема** (структура) базы;
- ``<имя_таблицы>.txt`` — **данные** конкретной таблицы.

Структура и данные **разделены**.


4. Схема базы (schema.txt)
===========================

Файл ``schema.txt`` хранит **структуру** базы: список таблиц и их колонки.

Формат строки::

    имя_таблицы|колонка1,колонка2,колонка3

Пример содержимого::

    users|id,name,age,email
    orders|id,user_id,amount

Разбор:

- ``users`` — имя таблицы;
- ``id,name,age,email`` — список колонок.

Разделитель между именем и колонками — символ ``|``.
Разделитель между колонками — запятая.


5. Данные таблиц (<имя>.txt)
=============================

Каждая таблица хранится **в отдельном файле**. Имя файла совпадает
с именем таблицы.

Формат строки::

    значение1|значение2|значение3

Пример содержимого ``users.txt``::

    1|Вася|20|vasya@mail.ru
    2|Петя|22|petya@mail.ru

Разбор:

- Одна строка файла = одна запись в таблице;
- Разделитель между значениями — символ ``|``.


6. Разделение структуры и данных
=================================

Ключевая идея архитектуры: **структура** и **данные** разделены.

::

    database/
     ├── schema.txt      ← ТОЛЬКО структура
     ├── users.txt       ← ТОЛЬКО данные users
     └── orders.txt      ← ТОЛЬКО данные orders

Что это даёт:

- быстрое получение списка таблиц (читать только ``schema.txt``);
- изменение структуры без потери данных;
- масштабируемость: много таблиц — много файлов;
- соответствие архитектуре настоящих СУБД.


7. Роли компонентов
====================

::

    main.py / tests.py          ← клиенты
            │
            │  импорт функций
            ▼
         db.py                   ← движок
            │
            │  чтение / запись
            ▼
    database/                    ← хранилище
     ├── schema.txt              ← структура
     └── <имя>.txt               ← данные


8. Поток данных
================

При вызове ``select("users")``:

::

    1. Пользователь: select("users")
    2. Движок: load_schema()
    3. Движок: read_lines("database/users.txt")
    4. Движок: разбивает строки по "|"
    5. Движок: возвращает матрицу
    6. Пользователь получает: [["1", "Вася", "20"], ...]

При вызове ``insert("users", ["1", "Вася", "20"])``:

::

    1. Клиент: insert("users", [...])
    2. Движок: load_schema() — проверить таблицу
    3. Движок: проверить число значений
    4. Движок: read_lines("database/users.txt")
    5. Движок: добавить строку
    6. Движок: write_lines("database/users.txt")
    7. При успехе — тишина. При ошибке — исключение.
