========================================
Архитектура проекта
========================================

1. Общая структура проекта
===========================

::

    my_db/
     ├── db.py                — движок СУБД (класс Database)
     ├── main.py              — демонстрация программного интерфейса
     ├── tests.py             — тесты (unittest)
     ├── ТЗ.rst               — техническое задание
     ├── ARCHITECTURE.rst     — архитектура проекта
     ├── ТП.rst               — технический проект
     └── database/            — папка с файлами базы данных
          ├── schema.txt       — схема базы (структура)
          ├── users.txt        — данные таблицы users
          └── orders.txt       — данные таблицы orders


1.1. Что внутри папки database/
--------------------------------

::

    database/                       ← БАЗА ДАННЫХ
     │
     ├── schema.txt                  ← СТРУКТУРА
     │    users|id,name,age,email
     │    orders|id,user_id,amount
     │
     ├── users.txt                   ← ТАБЛИЦА users
     │    1|Вася|20|vasya@mail.ru
     │    2|Петя|22|petya@mail.ru
     │
     └── orders.txt                  ← ТАБЛИЦА orders
          1|1|500
          2|2|1200


2. Назначение файлов
=====================

db.py
-----

**Движок СУБД.** Содержит:

- классы исключений;
- класс ``Database`` — все операции внутри;
- пользовательский интерфейс — методы класса.

Папка ``database/`` создаётся **автоматически** при создании объекта
класса (модуль ``os``). Файлы таблиц удаляются **физически**
через ``os.remove``.

main.py
-------

**Демонстрация** программного интерфейса. Работает с объектом класса
``Database``. Ловит исключения через ``try/except``. При успехе метод
молчит — программа не комментирует каждый шаг.

tests.py
--------

**Тесты** функций через модуль ``unittest``. **Класс** на каждую функцию,
**метод** на каждый сценарий. Используются ``assertEqual``, ``assertRaises``,
``setUp`` и ``tearDown``.

database/
---------

**Папка с файлами базы данных.** Создаётся **автоматически**
через ``os.makedirs`` при первом создании объекта ``Database``.


3. Формат хранения данных
==========================

База данных — это **папка** ``database/``. Внутри неё:

- ``schema.txt`` — **схема** (структура) базы;
- ``<имя_таблицы>.txt`` — **данные** конкретной таблицы.

Структура и данные **разделены**.


4. Схема базы (schema.txt)
===========================

Файл ``schema.txt`` хранит **структуру** базы: список таблиц и их колонки.

Формат строки::

    имя_таблицы|колонка1,колонка2,колонка3

Пример содержимого::

    users|id,name,age,email
    orders|id,user_id,amount

Разбор:

- ``users`` — имя таблицы;
- ``id,name,age,email`` — список колонок.

Разделитель между именем и колонками — символ ``|``.
Разделитель между колонками — запятая.


5. Данные таблиц (<имя>.txt)
=============================

Каждая таблица хранится **в отдельном файле**. Имя файла совпадает
с именем таблицы.

Формат строки::

    значение1|значение2|значение3

Пример содержимого ``users.txt``::

    1|Вася|20|vasya@mail.ru
    2|Петя|22|petya@mail.ru

Разбор:

- Одна строка файла = одна запись в таблице;
- Разделитель между значениями — символ ``|``.


6. Разделение структуры и данных
=================================

Ключевая идея архитектуры: **структура** и **данные** разделены.

::

    database/
     ├── schema.txt      ← ТОЛЬКО структура
     ├── users.txt       ← ТОЛЬКО данные users
     └── orders.txt      ← ТОЛЬКО данные orders

Что это даёт:

- быстрое получение списка таблиц (читать только ``schema.txt``);
- изменение структуры без потери данных;
- масштабируемость: много таблиц — много файлов;
- соответствие архитектуре настоящих СУБД.


7. Роли компонентов
====================

::

    main.py / tests.py          ← клиенты
            │
            │  создают объект Database
            ▼
         db.py                   ← движок
            │  класс Database
            │  хранит схему и пути в объекте
            │
            │  чтение / запись
            ▼
    database/                    ← хранилище
     ├── schema.txt              ← структура
     └── <имя>.txt               ← данные


8. Поток данных
================

При создании объекта::

    db = Database("database")

    1. Создаётся папка database/, если её нет (os.makedirs).
    2. Схема читается один раз и хранится в db.schema.
    3. Пути сохраняются в db.folder.

При вызове ``db.select("users")``::

    1. Клиент: db.select("users")
    2. Движок: проверяет self.schema
    3. Движок: read_lines("database/users.txt")
    4. Движок: разбивает строки по "|"
    5. Движок: добавляет первую строку — имена полей
    6. Клиент получает: [["id", "name", "age"], ["1", "Вася", "20"], ...]

При вызове ``db.select("users", "name,age")``::

    1. Клиент: db.select("users", "name,age")
    2. Движок: проверяет self.schema
    3. Движок: разбивает "name,age" по запятой
    4. Движок: ищет индексы колонок в схеме
    5. Движок: собирает строки только из выбранных колонок
    6. Клиент получает матрицу с заголовками

При вызове ``db.insert("users", ["1", "Вася", "20"])``::

    1. Клиент: db.insert("users", [...])
    2. Движок: проверяет self.schema
    3. Движок: проверяет число значений
    4. Движок: read_lines("database/users.txt")
    5. Движок: добавляет строку
    6. Движок: write_lines("database/users.txt")
    7. При успехе — тишина. При ошибке — исключение.
